PureFunction Backup — Privacy Policy

Applies solely to the private PureFunction Backup utility (separate from the Pure Function coaching application).

1. Scope and Intended User

PureFunction Backup is a private, owner-operated backup utility designed solely to store encrypted disaster-recovery backups of the Pure Function Supabase backend in the project owner's Google Drive account.

This utility does not offer public user registration or third-party account access. Coaching clients and coaches using the Pure Function web application do not connect their Google accounts to PureFunction Backup.

2. Google Drive API Usage and Permission Scope

PureFunction Backup requests only one Google OAuth 2.0 scope: https://www.googleapis.com/auth/drive.file.

With this limited scope, the utility performs only the following Google Drive operations:

  • Exchanges the owner's stored OAuth 2.0 refresh token at https://oauth2.googleapis.com/token for a short-lived access token when a backup run executes.
  • Finds or creates a dedicated app-owned folder in the owner's Google Drive (default name: PureFunction-Encrypted-Backups, or an explicitly configured app-accessible folder ID).
  • Uploads each encrypted backup archive (backup-<timestamp>.tar.gz.enc) and its companion verification manifest (backup-<timestamp>.manifest.json) using the Google Drive v3 Resumable Upload API.
  • Lists files strictly inside that backup folder to identify expired backup files and deletes only expired backup archives and their matching manifests according to the retention policy.

Because access is limited to drive.file, PureFunction Backup cannot view, read, modify, or delete any other files or folders in the owner's Google Drive. It does not access Gmail, Contacts, Calendar, or any other Google account data.

3. Encryption and Data Uploaded to Google Drive

Each backup run reads snapshots from the project's Supabase backend in read-only mode (PostgreSQL public, private, auth, storage, and supabase_migrations schemas plus Supabase Storage objects) into a temporary working directory on the backup runner.

  • Client-side encryption before upload: Every backup archive is compressed and encrypted before leaving the runner using AES-256-GCM (custom PFBK1 format) with a random 16-byte salt, random 12-byte IV, scrypt key derivation, and a 16-byte GCM authentication tag.
  • Pre-upload verification: Before upload, the utility verifies that the encrypted file decrypts cleanly and matches the original SHA-256 digest.
  • No unencrypted backups uploaded: Plaintext database dumps and storage files are never uploaded to Google Drive and are removed from the ephemeral runner working directory when the run finishes (including on error).
  • Non-PII manifest: The sidecar .manifest.json uploaded alongside each archive contains only technical verification metadata (format version, encryption label, storage provider, UTC timestamp, filenames, byte sizes, SHA-256 digests, and aggregate bucket/object counts). It contains no user credentials, encryption keys, client names, emails, or personal records.
  • Separate decryption key: The encryption passphrase (BACKUP_ENCRYPTION_KEY) is never uploaded to Google Drive and is stored separately in the project owner's secrets configuration.

4. Data Sharing and Limited Use

PureFunction Backup does not sell, rent, advertise with, or transfer Google user data or backup files to third parties, and does not use Google Drive data to train machine learning or AI models.

Data is transmitted only between the project's Supabase backend, the ephemeral backup execution runner (GitHub Actions when enabled by the owner), and Google Drive APIs over HTTPS. Known secrets, database passwords, JWTs, and Google OAuth tokens are redacted from error output.

5. Retention and Deletion

  • Automated retention pruning: After each successful upload, the utility evaluates backup files inside the backup folder matching the naming pattern backup-YYYY-MM-DDTHH-MM-SSZ.tar.gz.enc. Backups older than the configured retention period (default: 30 days, configurable between 7 and 3650 days) and their matching .manifest.json files are automatically deleted, while always preserving at least the newest configured minimum backups (default: 7 backups, configurable between 3 and 365). Non-backup files are never deleted.
  • Manual deletion: The project owner can delete any backup file or the entire PureFunction-Encrypted-Backups folder directly in Google Drive at any time.
  • Revoking access: The project owner can revoke PureFunction Backup's Google Drive authorization at any time through Google Account permissions at myaccount.google.com/permissions and delete the stored OAuth client secret and refresh token from GitHub Actions Secrets.

6. Operator Contact

PureFunction Backup is operated exclusively by the Pure Function project owner for internal backup storage. For questions about this policy or data handling, contact the project owner via the developer support contact email shown on the Google OAuth consent screen.
